# Model-Family Proposal Template

Provide the following before a family is added to any registry:

1. Namespaced family ID, owner, stability, and source provenance.
2. Distinct behaviors or scenarios that require the family.
3. Allowed model kinds, subject cardinality, perspective rules, target requirements, and required state fields.
4. Overlap analysis against every adjacent family and why an extension or role is insufficient.
5. Evidence types, derivation methods, uncertainty representation, privacy floor, and declassification policy.
6. Example valid and invalid records, queries, lifecycle transitions, and falsifiers.
7. PMRA scenario links and a conformance fixture.
8. Migration, deprecation, security, and psychometric-misuse risks.

New categories remain `EXPERIMENTAL` until independent evidence and interoperability justify promotion. Catalog size is not an objective.
