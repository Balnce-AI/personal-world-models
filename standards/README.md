# Standards integration strategy

The repository treats standards as **boundary profiles**.

- **HCP:** implement a scoped software-context projection profile and explore provenance/purpose/retention extensions.
- **MHS:** track and archive normative artifacts. Do not claim compatibility until schema/license/security details are public and tested.
- **ROS 2:** reference runtime adapter; never imply safety certification.
- **COVESA VSS/VISS:** vehicle signal semantics/data-access mapping.
- **SOVD:** diagnostics/support mapping.
- **W3C WoT:** Thing Description capability mapping.
- **OpenID/DIF/VC ecosystems:** reuse identity/selective-disclosure mechanisms rather than inventing new identity standards.

The question is not “which standard wins?” It is “which boundary can be translated without surrendering sovereign semantics?”
